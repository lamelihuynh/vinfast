final class InventoryService
{
  public static function decrement(
    PDO $pdo, string $productId, string $variantId, int $qty, ?string $strategy = null
  ): void {
    if (!$pdo->inTransaction()) {
      throw new LogicException('decrement() phải chạy trong transaction của bên gọi');
    }
    if ($qty <= 0) throw new InvalidArgumentException('qty phải > 0');

    $name = $strategy ?? (getenv('INVENTORY_STRATEGY') ?: 'atomic');
    $impl = match ($name) {
      'pessimistic' => new PessimisticStrategy(),
      'optimistic'  => new OptimisticStrategy(),
      'atomic'      => new AtomicStrategy(),
      'naive'       => new NaiveStrategy(),
      default       => throw new InvalidArgumentException("strategy không hợp lệ: $name"),
    };

    try {
      $impl->decrement($pdo, $productId, $variantId, $qty);
    } catch (PDOException $e) {
      $state = $e->errorInfo[0] ?? (string)$e->getCode();
      if (in_array($state, ['40001', '40P01', '55P03'], true)) {
        throw new ConcurrentUpdateException("SQLSTATE $state", 0, $e);
      }
      if ($state === '23514') {
        throw new OutOfStockException("$productId/$variantId", 0, $e);
      }
      throw $e;
    }
  }
}

interface InventoryStrategy
{
  public function decrement(PDO $pdo, string $productId, string $variantId, int $qty): void;
}

final class AtomicStrategy implements InventoryStrategy
{
  public function decrement(PDO $pdo, string $productId, string $variantId, int $qty): void
  {
    $st = $pdo->prepare(
      'UPDATE inventory
        SET stock = stock - :q, version = version + 1, updated_at = now()
        WHERE product_id = :p AND variant_id = :v AND stock - reserved >= :q
      RETURNING stock'
    );
    $st->execute([':q' => $qty, ':p' => $productId, ':v' => $variantId]);
    if ($st->fetchColumn() === false) {
      throw new OutOfStockException("$productId/$variantId");
    }
  }
}
T5-10

PessimisticStrategy và NaiveStrategy

~4h · Phụ thuộc: T5-09 · PG

Pessimistic khóa dòng bằng SELECT … FOR UPDATE (row lock, giữ tới khi commit, theo 2PL nghiêm ngặt). Naive đọc rồi ghi giá trị tuyệt đối, cố ý để lộ lost update.

Các bước

  1. Pessimistic: SELECT FOR UPDATE → kiểm tra stock - reserved >= qty → UPDATE. Env tùy chọn INVENTORY_LOCK_TIMEOUT_MS → SET LOCAL lock_timeout (hết giờ: 55P03).
  2. Naive: SELECT không khóa → kiểm tra → usleep(NAIVE_SLEEP_US) (mặc định 2000) → ghi giá trị tuyệt đối. Chỉ cho phép khi APP_ENV=bench.
  3. Biến thể cho báo cáo: naive ghi stock = stock - :q thì CHECK stock >= 0 chặn (23514) thay vì bán vượt: chốt chặn cuối của quyết định 3.

File

  • app/services/inventory/PessimisticStrategy.php, NaiveStrategy.php MỚI

Kiểm tra

  • Hai psql: A BEGIN; SELECT … FOR UPDATE;, B chạy pessimistic qua bench.php → B treo tới khi A COMMIT (thấy trong pg_locks với granted = f).
  • k6 thử nhanh 100 request với naive (sau T5-12): số đơn thành công > 10.
final class PessimisticStrategy implements InventoryStrategy
{
  public function decrement(PDO $pdo, string $productId, string $variantId, int $qty): void
  {
    if ($ms = (int)getenv('INVENTORY_LOCK_TIMEOUT_MS')) {
      $pdo->exec("SET LOCAL lock_timeout = '{$ms}ms'");
    }
    $sel = $pdo->prepare(
      'SELECT stock, reserved FROM inventory
        WHERE product_id = :p AND variant_id = :v FOR UPDATE'
    );
    $sel->execute([':p' => $productId, ':v' => $variantId]);
    $row = $sel->fetch(PDO::FETCH_ASSOC);
    if (!$row || (int)$row['stock'] - (int)$row['reserved'] < $qty) {
      throw new OutOfStockException("$productId/$variantId");
    }
    $pdo->prepare(
      'UPDATE inventory SET stock = stock - :q, version = version + 1, updated_at = now()
        WHERE product_id = :p AND variant_id = :v'
    )->execute([':q' => $qty, ':p' => $productId, ':v' => $variantId]);
  }
}

T5-11

OptimisticStrategy (cột version)

~3h · Phụ thuộc: T5-09 · PG

Đọc không khóa, ghi có điều kiện theo version. Không ghi được → ConcurrentUpdateException, OrderService của T4 retry toàn bộ transaction.

Các bước

  1. SELECT không khóa; thiếu hàng → OutOfStockException. UPDATE có version = :ver; rowCount() === 0 → ConcurrentUpdateException, tăng InventoryService::$conflicts.
  2. Cơ chế (cho báo cáo): dưới READ COMMITTED, UPDATE chờ khóa dòng rồi đánh giá lại WHERE trên bản mới; version đã tăng nên khớp 0 dòng.
  3. Rủi ro: 100 request trên 1 SKU, retry 3 lần có thể chưa bán hết 10. Đo ở T5-13; nếu xảy ra, đề xuất T4 thêm backoff 1–5 ms và ghi vào báo cáo.

File

  • app/services/inventory/OptimisticStrategy.php MỚI

Kiểm tra

  • Hai psql: A đọc version = 0; B trừ kho thành công (version = 1); A chạy UPDATE với version = 0 → UPDATE 0.
  • php bench/t5/smoke_contract.php --strategy=optimistic qua hết.
final class OptimisticStrategy implements InventoryStrategy
{
  public function decrement(PDO $pdo, string $productId, string $variantId, int $qty): void
  {
    $sel = $pdo->prepare(
      'SELECT stock, reserved, version FROM inventory WHERE product_id = :p AND variant_id = :v'
    );
    $sel->execute([':p' => $productId, ':v' => $variantId]);
    $row = $sel->fetch(PDO::FETCH_ASSOC);
    if (!$row || (int)$row['stock'] - (int)$row['reserved'] < $qty) {
      throw new OutOfStockException("$productId/$variantId");
    }
    $upd = $pdo->prepare(
      'UPDATE inventory
        SET stock = stock - :q, version = version + 1, updated_at = now()
        WHERE product_id = :p AND variant_id = :v
        AND version = :ver AND stock - reserved >= :q'
    );
    $upd->execute([':q' => $qty, ':p' => $productId, ':v' => $variantId, ':ver' => (int)$row['version']]);
    if ($upd->rowCount() === 0) {
      InventoryService::$conflicts++;
      throw new ConcurrentUpdateException("version {$row['version']} đã cũ");
    }
  }
}

public static function adjust(string $productId, string $variantId, int $newStock, int $expectedVersion): bool
{
  global $pdo;
  $st = $pdo->prepare(
    'UPDATE inventory SET stock = :s, version = version + 1, updated_at = now()
      WHERE product_id = :p AND variant_id = :v AND version = :ver AND reserved <= :s'
  );

import http from 'k6/http';
import { check } from 'k6';
import { Counter } from 'k6/metrics';

const N = Number(__ENV.N || 100);
const MODE = __ENV.MODE || 'hot';
export const options = {
  scenarios: { race: { executor: 'per-vu-iterations', vus: N, iterations: 1, maxDuration: '120s' } },
};
const C = Object.fromEntries(['ok', 'out_of_stock', 'conflict', 'error', 'retries'].map(k => [k, new Counter(k)]));

export default function () {
  const pid = MODE === 'hot' ? 'bench-hot' : 'bench-s' + String((__VU % 100) + 1).padStart(3, '0');
  const res = http.post(`${__ENV.BASE || 'http://app'}/bench.php`, {
  user_id: String(900000 + __VU), product_id: pid, variant_id: pid + '-STD',
  qty: '1', strategy: __ENV.STRATEGY,
  });
  const body = res.json() || {};
  C.retries.add(body.retries || 0);
  (C[body.result] || C.error).add(1);
  check(res, { 'status 200/409': (r) => r.status === 200 || r.status === 409 });
}

export function handleSummary(data) {
  const f = `/bench/results/raw/t5_${__ENV.STRATEGY}_${MODE}_${N}_${__ENV.RUN || 1}.json`;
  return { [f]: JSON.stringify(data), stdout: '' };
}

  1. Race condition. Đọc-kiểm tra-ghi không nguyên tử gây bán vượt, lost update; mở đầu bằng kết quả naive (thí nghiệm A).
  2. Khóa trong PG. Strict 2PL; khóa dòng FOR UPDATE, UPDATE tự lấy khóa dòng; phát hiện deadlock (40P01) và tránh bằng thứ tự khóa cố định.
  3. MVCC. xmin/xmax, đọc không chặn ghi; snapshot theo câu lệnh (RC) và theo transaction (RR); UPDATE dưới RC đánh giá lại WHERE sau khi chờ khóa (nền của atomic và optimistic).
  4. So sánh 4 chiến lược. Tính đúng, throughput, p95, retry, deadlock, độ phức tạp. Optimistic hợp khi ít tranh chấp, kém khi 1 SKU nóng; pessimistic xếp hàng nhưng không retry; atomic gọn nhất. Vai trò CHECK stock >= 0.
  5. Isolation level và hiện tượng bất thường. Bảng dưới + kết quả 6 kịch bản giỏ hàng.
  6. Hạn chế, mở rộng. Luồng reserved, SERIALIZABLE (SSI) cho write skew, so sánh findOneAndUpdate có điều kiện trên Mongo.
